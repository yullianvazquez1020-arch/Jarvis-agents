# Business conversation

Jarvis has six analytical specialties: coordinator, ISLAFIX, commerce, research,
marketing and finance. They are instructions for the existing conversational
model, not six processes or separate paid model calls. Existing commands remain.

During open-ended discussion Jarvis is instructed to contribute an observation
and ask one topic-specific follow-up, then use the owner's answer in the next
turn. Quick requests and goodbyes do not force a question. Short replies use the
preceding exchange, and ambiguous references require clarification. Silence does
not trigger repeated prompts. This is conversational guidance, not a background
agent or a change to action authorization. Actual conversational quality must be
evaluated with the owner; passing code tests does not establish model compliance.

The `business_context` tool reads the same durable owner facts, internal store
plan, note index and saved research across authenticated channels. It includes
source dates when present, unavailable sources and size omissions. It distinguishes
owner statements from verified account activity. Specialist views can include
job or accounting summaries through existing readers. No purchases, publishing,
client messages or configuration changes occur in this tool.

Dialogue history stays isolated per device. The existing durable history resumes
follow-up conversations after a server restart; other devices can consult shared
business records but do not receive each other's chat histories. This does not
recover missing historical businesses or turn an internal plan into a sale.

Short explicit panel requests retain their shortcuts. Questions such as “How can
we improve collections?” continue to the model rather than opening a collections
panel. The desktop retains its existing English response instructions.

This change does not fix local microphone rearming, add voice interruption,
accelerate transcription, or perform a live research search by itself. Research
from this tool is saved research, labelled accordingly. Existing research and
note tools remain available according to each channel's permissions.

Tests use simulated model responses and local storage. They verify retrieval,
multi-turn history restoration, isolation, bounded output and action boundaries;
they do not establish subjective voice quality or real-world conversation latency.
